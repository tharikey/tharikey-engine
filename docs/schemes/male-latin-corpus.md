# Malé Latin (corpus)

`male-latin-corpus` · **text** · not reversible · the everyday Malé Latin romanization plus a
data-mined correction layer. Higher word-accuracy than [`male-latin`](male-latin.md), at the cost of a
shipped rule set.

```text
kandu  →  ކަނޑު      (male-latin gives ކަންޑު; the rewrite restores the prenasal)
```

## What it is

It inherits everything from [`male-latin`](male-latin.md) (`base = "male-latin"`) and adds a
[`[rewrites]`](../scheme-format.md#rewrites-post-composition-corrections-fst-inspired) block — an ordered
list of context-rewrites applied to the composed Thaana, *after* the abugida and coda rules. Each rule
replaces a short substring in a given left/right context, correcting systematic cases the hand-written
rules miss (context-conditioned prenasalisation, `koh`-family stems, specific final-glottal letters).

The rules are **data-mined and net-scored**, not hand-curated — see
[the architecture](../architecture.md#rewrites-an-optional-post-correction-layer-fst-inspired). On a
held-out split it scores **+4.14 pts word-exact** over `male-latin`. The rules *generalise* (they hold on
words never seen during mining), so the scheme is still **lexicon-free** — it ships rules, not a wordlist.

## When to use which

| | `male-latin` | `male-latin-corpus` |
|---|---|---|
| Curation | hand-written, fully auditable | data-mined (offline pipeline) |
| Accuracy | the deterministic baseline | +4.14 pts (held-out) |
| Reversible | ✓ (lossy) | — (the rewrites aren't cleanly invertible) |
| Ships | nothing | the mined rule set |

Use `male-latin` when you want the auditable, reversible baseline; use `male-latin-corpus` when forward
word-accuracy matters more than reversibility.

## Regenerating the rules

The `[rewrites]` block is generated by the toolkit's offline mining pipeline (which lives outside this
engine) from the cross-agreement-cleaned corpus (politecat314 + alakxender pairs). The file is generated —
re-run the pipeline rather than hand-editing it.
